# Direct Vercel deployment

The app is deployed from the local source without Render or GitHub, using Vercel Services (beta):

- Team: `resum-projects` (Resume_Projects)
- Project: `returnwise-ai` (`prj_IOGHHiC985xsEcVYWNNk4CE2z4Ud`)
- Frontend: Next.js service rooted at `frontend/`
- Backend: Python Docker service rooted at the repository, built with `Dockerfile.vercel`
- Database: free Neon PostgreSQL resource `returnwise-db`, Singapore
- Routing: `/api/*` and `/reports/*` go to Python; all other paths go to Next.js

`VERCEL_SERVICES=1` disables the standalone Next.js proxy. The top-level `vercel.json` owns ingress, so no public `API_URL` is needed for this deployment. Database environment variables are managed by the Neon integration; login settings and the service API key are Vercel secrets. Never commit `.env.local`, `.vercel`, or `.deployment-tools`.

The backend image builds deterministic synthetic datasets, EDA and model artifacts. At cold start it applies migrations under a PostgreSQL advisory lock and imports the demo only when the database is empty. Training artifacts are regenerated by a new image build. Retrained artifacts inside a running container are ephemeral and are not preserved across redeploys.

The production login credentials are saved locally in the ignored `.deployment-tools/deployment-login.json` file. They are not part of the uploaded source. Treat that file as a password. The included development demo credentials do not grant access to this deployment.

For future releases, inspect the linked project before deployment, then stage a production build, verify it and promote the same build:

```powershell
node .deployment-tools/node_modules/vercel/dist/vc.js project inspect --non-interactive
node .deployment-tools/node_modules/vercel/dist/vc.js deploy --prod --skip-domain --scope resum-projects
node .deployment-tools/node_modules/vercel/dist/vc.js promote <verified-deployment-url> --scope resum-projects
```

The local CLI is authenticated to Resume_Projects. The separately connected plugin may still target a different account; verify its owner before using it for mutations.
